## Implementation boundaries

Extend current tables additively; retain existing route URLs, preferences, data, model configuration, tools, prompts and approval contracts. Keep provider conversation internals out of dashboard snapshots and expose only user-facing task instructions, action summaries, outputs and tool evidence. Task stop/pause takes effect at safe execution boundaries; never pretend an already-sent Studio mutation was undone. Imported metrics must carry a source, observation time and quality label. Imports and explicit uploads are stored locally; importing a file never executes or publishes it.

## Data and execution details

`worker/migrations.ts` performs transactional additive migrations. Existing settings, prompts, games and runs are retained. Legacy runs keep automatic orchestration; new requests may opt into plan approval. Task and run cancellation stop future execution at safe boundaries; completed Studio operations and uncertain outcomes remain inspectable. Rejections/change requests retain exact tool arguments and notes. Artifact changes create one linked task for the producing agent; tool-call feedback resumes the original producing task with the user note. Repeated identical approvals and artifact verdicts are idempotent; conflicting decisions fail.

Full provider conversations/reasoning remain private to the runtime. Only response content, explicit user requests, concise action summaries, and tool evidence enter the work panel. Streaming assembles tool-call deltas before execution and retains budget reservations on interrupted streams or invalid usage accounting. The implementation follows [OpenRouter streaming](https://openrouter.ai/docs/api/reference/streaming) and [usage accounting](https://openrouter.ai/docs/cookbook/administration/usage-accounting); it does not send deprecated usage flags.

Existing projects acquire a `prototype` lifecycle label by default; stages are user-maintained, not a claim of verified launch status. A pitch can create a Studio-independent planning project. Execution approval must bind an unbound planning run to an actual Studio instance. Existing pinned runs are never redirected by a project switch.

## Configuration and remaining external limits

- Keep the existing `OPENROUTER_API_KEY`, model settings and official Studio MCP command. No new credentials are required for local features. Paid completions and real Roblox execution were not used in validation.
- Market import: `{source, fetchedAt, quality, category, games:[{universeId,title,rank?,players?,likes?,votes?,visits?,genre?,description?,url?}]}`. No growth is displayed without two compatible source/category/quality snapshots.
- Analytics import: `{gameId, source, fetchedAt, quality, metrics:[{metric,points:[{at,value,series?}]}]}`. Supported metrics are `dau`, `online`, `revenue`, `spent`, `first_minute`, `session`, `playtime`; units are fixed by the contract. Times normalize to UTC and future/duplicate observations are rejected.
- There is no automatic Roblox telemetry ingestion, proprietary market access, player-level session database, publishing, rollback, or automatic asset installation. Those require an authorized integration rather than invented data or a cosmetic control.
